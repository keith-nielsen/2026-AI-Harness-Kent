# Adopted learnings

Curated by Kent from Gent projects. New Gents inherit these.

## Avoid conflating empirical formulas with first-principles derivations

The project failed because it presented the Akasofu epsilon function as a direct derivation from Poynting flux without acknowledging its empirical and geometric origins. In future scientific modeling, always clearly distinguish between theoretically derived equations and empirically fitted or geometrically motivated parameters to prevent misleading physical interpretations.

_Source: gent-d3170b46 learning #3. Kent: Reusable for any scientific or modelling task: label empirical or fitted formulas as such and keep them apart from first-principles derivations (the Akasofu example is incidental)._

## Implement independent verification scripts for complex arithmetic

The project included separate Python scripts (`verify_calc.py`, `verify_epsilon.py`) to independently check the manual calculations. This technique ensures numerical accuracy in quantitative models and should be standard practice for any project involving significant arithmetic or formula application.

_Source: gent-d3170b46 learning #4. Kent: Concrete and reusable: check hand calculations with a small script (Gents have Run Script), for any quantitative task._

## Use structured data (JSON) for intermediate state persistence

Storing intermediate results in a structured format like output5.json enables later tasks or verification scripts to ingest previous outputs programmatically. This creates a reliable data pipeline, avoiding the fragility of parsing text-based outputs.

_Source: gent-4d3f9706 learning #3. Kent: Reusable for multi-task Gents: pass results between tasks as JSON files instead of re-parsing prose, which small models get wrong._
